# K210 基础版：人脸 → 额头 → rPPG

现在只运行 **`k210_rppg_basic.py`**（`1.2.0-basic-rppg`）。适用已有的 Maix Bit / OV2640 / MaixPy v1 固件；人脸模型继续使用 Flash `0x300000`。默认尝试 POS，并通过串口输出同窗口 GREEN 候选作为对照。

## 在 MaixPy IDE 运行

1. 停止之前的程序，打开 `k210_rppg_basic.py`，整文件运行。
2. 启动时应看到 `# version=1.2.0-basic-rppg`。保留已确认的上下、左右翻转设置。
3. 让一张正脸进入画面。红框是当前人脸检测框，绿框是额头采样区域；确认绿框落在裸露额头上。
4. 正常坐好，先用稳定照明测试。积累约 10 秒额头数据后，每秒计算一次 `EXP ... BPM`。
5. 默认持续运行，按 IDE 停止键结束。结束时显示 `STOPPED`；程序不修改启动文件、不烧录固件。

首次候选出现时间还取决于实际帧率和计算耗时，尚未在开发板验证。

右上角两行右对齐显示即时 FPS 和当前图像宽×高（默认 `320x240`），距离右边缘 4 像素。FPS 按实际帧间隔计算，包含两次采图之间的检测、计算、LCD 与串口开销；首帧显示 `FPS:--`。

左下角青色曲线无标题，占四分之一屏宽、48 像素高（当前为 80×48），背景透明，直接叠加在摄像头画面上。横轴始终显示最近 5 秒，按真实时间向左滚动；纵轴固定为 `-PLOT_Y_LIMIT` 到 `+PLOT_Y_LIMIT`，默认 ±1.0 个 G 通道均值单位（0–255 刻度上的差值，不是百分比）。中央灰线为零，±1.0 分别映射到中央上下 18 像素，超过范围只在显示上截到边缘，不会自动缩放。

`PLOT_RECALCULATE` 控制显示方式，默认 `True`：

- `True`：每帧对最近 5 秒 G 拟合直线，减去平均水平和整体升降趋势。新数据或窗口边界变化会改变拟合，旧点的显示高度也会变化；原始数据没有被改写。
- `False`：每个新点只减去当时的实时基线，保存高度，之后只向左平移，直到移出画框。基线用实际时间间隔做指数更新，时间常数 `PLOT_BASELINE_MS=1000` 毫秒；显示点在采样时限频保存，重画不重新挑选旧点。

修改开头开关并重新运行即可切换。两种方式固定同一坐标尺度，但去基线方式不同，切换时波形形状可能改变。程序持续维护小型固定点缓存，不参与心率估计；曲线仍显示 G 的变化，即使 BPM 选择了 POS。它不表示 ECG 或已验证的脉搏波。漏检间隔可能由连线跨过；没有新样本时曲线随时间向左移出，不会每 5 秒清屏重扫。绘图在颜色采集后执行，最多连接 65 个显示点，不改变原始 RGB 或心率算法。

## 处理流程

每帧 YOLOv2 检测 → 选择最大人脸框 → 按比例取额头 → 采集平均 RGB → 最近 10 秒 RGB → 按真实时间重采样 → POS 或 GREEN 提取 → 去线性趋势 → 带通滤波 → Hann 窗 → 搜索频带内最大频谱峰 → BPM。

- 没有 KLT、光流、角点跟踪或检测框平滑。额头直接跟随当前人脸框，所以仍可能随检测框抖动。
- 没有运动、颜色阶跃、ROI 跳变触发的历史重置，也没有峰值比、峰集中度或连续两次确认门槛。
- 当前帧没检测到脸，只跳过采样并隐藏 BPM；不复制上一帧颜色。已有真实样本按时间自然过期。
- 窗口内的缺失区间作线性插值，没有额外缺口拒绝规则。连续漏检超过窗口后，旧数据自然过期，需要重新积累。
- 颜色在画框之前读取。原始 RGB 保留原值，处理仅作用于临时信号数组。只有一份有界 RGB 历史，两个算法使用相同的采样和重采样网格。
- 这是独立的 POS/GREEN 实现，不是 Heartbeat/OpenCV 流程的完整复现。

1.2.0 增加 [Wang 等人的 POS 算法](https://doi.org/10.1109/TBME.2016.2609282)，依据原论文 Algorithm 1 独立实现。每个约 1.6 秒子窗口将 R/G/B 分别除以各自均值，投影为 `G-B` 和 `-2R+G+B`，按标准差比例相加，再去均值并重叠相加。代码包含直到最后一个样本的完整子窗口，不按重叠次数取平均。输出是无量纲信号。POS 核心之后仍使用本项目既有滤波和频谱流程，属于本项目的组合方案，并非原论文裸 POS 的完整复现。

目标是减弱部分 RGB 共同亮度扰动。默认 `HR_METHOD="POS"`，`COMPARE_METHODS=True` 同时计算 GREEN 并输出两组候选；不融合、不自动切换。R/B 的量化噪声、低照度和运动仍可能让 POS 表现更差。`HR_METHOD="GREEN"` 可恢复原来的单通道估计；`COMPARE_METHODS=False` 只计算选中的方法，减少运算。是否更准需用同一时间段的参考心率判断，两个算法相同也不等于正确。

1.1.0 增加 10 秒分析窗口和轻量带通滤波，尝试减弱带外亮度扰动、改善频率估计。滤波使用二阶 Butterworth 高通与低通串联，正反向处理，截止频率取搜索范围的 0.7–4 Hz；以最多 2 秒奇反射填充减轻边界瞬态。填充只用于计算，不计入真实采样历史。高截止频率达到或超过 Nyquist 时省略低通，频率搜索仍限制在可表示范围内。带通滤波是常见的 rPPG 处理步骤，可参阅 [pyVHR 论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC9044207/)；这里的参数和实现仍需本项目实测。

滤波不能消除搜索频带内的运动或光照干扰，也不能修复已经发生的混叠。较长窗口会让心率变化的响应更慢。曲线是最近 5 秒 G 的显示诊断，BPM 使用 10 秒窗口并另加带通滤波；曲线形状不等于 BPM 输入信号形状。

数据不足时显示 `WARMUP`；去趋势后为数值零时显示 `NO SIGNAL`；采样率不能表示搜索频带时显示 `LOW RATE`；容量不足以覆盖窗口时显示 `BUFFER LIMIT`。POS 子窗口有通道均值不大于零时为 `NO RGB`；第二投影无变化而第一投影有变化、无法计算标准差比例时为 `POS DEGENERATE`。这些是数据与计算条件，不是额外峰值质量筛选；噪声仍可能产生候选。未启用的对照算法在串口标记 `DISABLED`。

## 参数

修改文件开头的常量即可：

| 参数 | 默认值与含义 |
| --- | --- |
| `CONFIDENCE` / `NMS` | 0.30 / 0.30，沿用已用过的检测参数 |
| `FOREHEAD` | `(0.30, 0.10, 0.40, 0.15)`，人脸框内 x/y 偏移及宽/高比例；横向 30%–70%、纵向 10%–25% |
| `SAMPLE_STEP` | 1 像素，对额头 ROI 内所有像素取平均；改为 2 或 3 可减少采样开销 |
| `WINDOW_MS` / `UPDATE_MS` | 10000 / 1000 毫秒，信号窗口与计算间隔 |
| `PLOT_WINDOW_MS` | 5000 毫秒，左下角曲线的显示时长 |
| `PLOT_RECALCULATE` | `True`，整段曲线重新去趋势；`False` 只平移生成后高度固定的点 |
| `PLOT_Y_LIMIT` | 1.0，固定纵轴半范围，须大于 0；设为 2.0 可容纳更大波动，0.5 可放大小波动 |
| `PLOT_BASELINE_MS` | 1000 毫秒，固定点显示方式的基线时间常数，须大于 0 |
| `HR_METHOD` / `COMPARE_METHODS` | `"POS"` / `True`，LCD 采用的算法，以及是否计算另一个算法的对照候选 |
| `POS_WINDOW_MS` | 1600 毫秒，POS 子窗口；样本数为 `ceil(1.6*重采样率)`，至少 3 个 |
| `BANDPASS_ENABLED` | `True`；改为 `False` 可比较同一窗口长度下的滤波效果 |
| `MIN_BPM` / `MAX_BPM` | 42 / 240 BPM；上界也受重采样率的 Nyquist 限制 |
| `BPM_STEP` | 3 BPM，频谱搜索步长，不代表测量准确度 |
| `MAX_SAMPLES` | 256 个真实 RGB 样本，另有至多 66 个显示点和有限的临时计算数组 |
| `LOG_SAMPLES` | `True`，每帧 RGB/ROI/时间输出到串口；不在板上缓存整轮日志 |
| `RUN_SECONDS` | 0 持续运行；改为 60 可运行约一分钟 |

算法用最多 128 个均匀时间点计算频谱，插值不能增加真实信息。10 秒观测时长对应约 0.1 Hz（6 BPM）的基本频率尺度，Hann 窗也影响分辨能力；3 BPM 搜索步长不能理解为 3 BPM 准确度。要对照 1.0.x 的处理方式，可同时设置 `WINDOW_MS=5000`、`BANDPASS_ENABLED=False`。

1.0.2 将额头空间采样步长从 3 改为 1，图像仍为 320×240。例如 40×18 的额头区域，现在平均 720 个像素，之前是 84 个。目标是利用更多像素做空间平均；实际信号改善与 FPS 代价尚待实机比较，可查看屏幕 FPS 和串口 `sample_ms`。这不增加真实视频帧数，也不自动排除 ROI 内的头发或背景。

## 输出与可选收数工具

约每秒通过现有 USB 串口输出一行 `# HR_RESULT`：

| 字段 | 含义 |
| --- | --- |
| `t_ms` / `state` | 当前采样的相对时间（毫秒）与状态 |
| `fps` | 与 LCD 相同的即时整循环帧率；首帧未知时为 -1 |
| `bpm` / `bpm_t_ms` | 候选心率及其源窗口结束时间；无候选时均为 -1 |
| `method` | LCD/`bpm` 使用的算法，`POS` 或 `GREEN` |
| `pos_bpm` / `green_bpm` | 两种方法的候选，缺失或未启用为 -1 |
| `pos_state` / `green_state` | 各方法状态；未启用为 `DISABLED` |
| `compare_t_ms` | 最近已计算的共同窗口结束时间，尚未计算或无脸时为 -1；计算无候选时仍保留此时间 |
| `g` / `n` | 当前额头 G 均值与保留的真实信号样本数；无脸时 G 为 -1 |
| `dt_ms` | 相邻采图的真实时间差，毫秒 |
| `detect_ms` / `sample_ms` / `hr_ms` | 检测、采样与窗口更新、心率计算的耗时，毫秒 |
| `valid` | 固定为 0，表示尚未通过真人参考验证 |

上位机可筛选以 `# HR_RESULT;` 开头的行，再按分号和等号解析字段；串口收数工具默认 115200 波特。`LOG_SAMPLES=False` 可关闭逐帧 CSV，只保留周期结果和启动/停止信息。计算仍全部在 K210 上完成。

启动会输出采图、首次检测、首次颜色采样阶段，以及当前窗口长度、带通开关、采样步长、算法和绘图模式。`# CAPABILITIES` 只在第一帧检查一次 `find_displacement` 和 `ulab.linalg.inv` 是否存在，1 表示存在，0 表示没有该接口；没有实际运行光流或求逆，也不是速度测试。

逐帧 CSV 的 `t_ms` 是 `sensor.snapshot()` 返回后的相对时间，`dt_ms` 是相邻采样时间差，不是曝光时间。ROI 单位为原图像素；RGB 是 RGB565 展开的 0–255 通道均值，不是物理辐照度。缺失颜色填 `-1`。`bpm_t_ms` 是当前候选的源窗口结束时间；每帧显示不等于每帧计算。1.2.0 保留原 17 列顺序，在 `fps` 后追加 `method,pos_bpm,green_bpm,pos_state,green_state,compare_t_ms`，共 23 列。无脸会隐藏并清除两组候选，不删除采样历史；重新检测到脸后，等待下一次计算。

电脑收数工具只保存串口输出，心率仍在板上计算。先断开 IDE 串口，再在项目目录执行：

```powershell
powershell -NoProfile -File .\tools\run_capture.ps1 -Port COM3 -TimeoutSeconds 60
```

工具运行基础脚本，保存新的 `captures/*.txt`，约 60 秒后发送 Ctrl-C 停止。串口停止流程尚待实机验证；未收到结束确认会明确报告。

## 当前验证边界

以前已在开发板运行过摄像头、YOLOv2 人脸检测、颜色采集和 LCD 显示。这些接口和人脸模型被保留。

**新脚本尚未在开发板运行，也没有已验证的真人心率结果。** `EXP` / `valid=0` 表示候选值。去掉筛选以后，噪声也可能产生数字；先确认框、采样和计算连续运行，再和同一时段参考心率比较。

基础版假设只有一个人。多脸时选择最大框，可能换人并混入旧信号。遮挡、检测框抖动、漏检插值和相机自动曝光都会干扰结果；没有增加曝光锁定调用，现有自动控制状态仍未验证。

电脑检查：

```powershell
python -B -m unittest discover -s tests -v
powershell -NoProfile -File .\tools\run_capture.ps1 -SelfTest
```

已通过 22 项合成信号/模拟采集循环检查，包括独立 NumPy POS 公式对照、SciPy 滤波对照、带外抑制、已知脉搏频率、10 秒积累、缺失通道/退化投影及串口字段一致性。合成的 72 BPM 脉搏叠加强烈 102 BPM 共同亮度干扰时，POS 返回 72、GREEN 返回 102；这只是构造场景，不是真人准确度。NumPy/SciPy 仅供电脑测试，板端没有依赖；电脑缺少依赖时跳过对应对照项。收数工具协议解析和 MicroPython v1.11 语法检查仍属于软件验证，不证明用户固件完整 API、板端运行速度或准确度。

## Heartbeat 仓库核对与可借鉴内容

核对了 [prouast/heartbeat 的 RPPG.cpp](https://github.com/prouast/heartbeat/blob/master/RPPG.cpp) 与 [opencv.cpp](https://github.com/prouast/heartbeat/blob/master/opencv.cpp)。它的额头区域同样是横向 30%–70%、纵向 10%–25%，做区域颜色平均、去趋势、平滑和频谱峰值估计；也提供 PCA 和 RGB 组合 `xminay`。本次 POS 来自前述论文，不是该仓库的 `xminay` 实现。仓库的重检测跳变补偿依赖重检测标记，不适合直接用于本项目每帧 YOLO 的流程。失脸清空历史的行为也没有沿用。

它的 `draw()` 同时画时域波形和频谱，后者有助于检查候选峰。但两幅图按当前最小/最大值缩放，位置和尺寸跟随脸框；本项目保留固定小图及双模式开关，暂未增加频谱图。频谱峰高或图形好看本身不能证明是脉搏。

不能据此认定 K210 完全不支持运动估计或矩阵求逆：

- [MaixPy v1 图像文档](https://wiki.sipeed.com/soft/maixpy/en/api_reference/machine_vision/image/image.html) 提供 `image.find_displacement()`，使用相位相关，能做运动估计；它不是 OpenCV `calcOpticalFlowPyrLK` 的直接替代。本地 MaixPy 源码也有该接口及条件编译开关，未找到仓库所用 KLT/仿射估计的同名 Python 接口。
- [v0.6.2 更新记录](https://github.com/sipeed/MaixPy-v1/releases/tag/v0.6.2) 已包含 `ulab`；[旧版 ulab 文档](https://micropython-ulab.readthedocs.io/en/1.7.9/ulab/linalg/index.html) 提供 `linalg.inv()`，但实际可用性由固件构建决定。当前板端是 `v0.6.2-44-gd9dc6c58c`；本地源码基线为 `d8901fd...`，不能当作这份固件的接口实测证明。
- 仓库去趋势显式构建 N×N 矩阵并求逆。以 N=128 为例，仅一个 float32 矩阵就是 64 KiB，还需要临时数组；这能说明需要评估开销，不能断言板子一定跑不了。可以另写带状方程求解实现相同数学目标，也无需完整 OpenCV；本轮未加入该算法。

下次运行查看 `# CAPABILITIES` 可确认两个接口是否暴露。当前 POS/GREEN 都不依赖它们，尚未做板端光流、矩阵求逆或二者与 KPU 同时运行的耗时测试。

文件末尾 `IDE_EOF_GUARD` 故意没有最终换行，保留之前的旧 IDE 兼容措施。编译产生的 `.mpy` 只留在电脑临时目录，不用于替换板上源码。
